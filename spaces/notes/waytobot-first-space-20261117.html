一句话

WayToBot 是三个 Grokbot/Muse 重度用户为小白建的免费入门社区；本场最有料的是两块硬货——铁柱总结的 Grokbot 省额度六条军规，和 Kim 梳理的用 Personal Agent 变现的四条路（跨境电商、自媒体、2B 企业服务、AI 短剧与独立开发）。

WayToBot 社区：谁发起、定位是什么

  • 核心发起人：蓝哥、Kim、铁柱三人；嘉宾团约 10 位早期成员（李九二、阳文、小文、麦当、LK 等）
  • 起因：三人是最早把 Grokbot、Muse 用得最深的一批创作者，在推特输出了大量教程、累计几百万阅读量；小群里聊着聊着，觉得应该把聊天范围扩大，帮更多不了解 Grokbot/Muse 的人入门
  • 时间线（发言人说法）：xAI 8 月 11 日推出 Grokbot，Meta 9 月推出 Muse，随后 OpenAI 的 Dots、Manus 等跟上，"这一轮 Personal Agent 感觉产品是紧喷的"
  • 定位：帮大家做小白入门 Personal Agent 的社区，做高质量信息的筛选；每周或每两周开一次 Space，邀请厉害的嘉宾分享交流
  • 提供三样东西：① Grokbot、Muse、OpenAI Dots、Manus 等所有 Personal Agent 的最新新闻与功能资讯；② 定期线上嘉宾分享（含 QA 环节）；③ 免费群里持续分享优质信息与教学
  • 不提供：付费群才有的定制服务与更深入的服务，"毕竟是免费的嘛"
  • 官网已上线，后续会增加新手入门教程与实战案例；欢迎共建——有好案例可申请当分享者，社区帮你安排分享、给曝光与增长机会
  • 规模：已开十几个微信群；下期主题已定：Grokbot + 电商（下周一请跨境电商行业嘉宾展开分享）；另预告 12 月 12 日 Grokbot 在深圳办 Grokbot + 硬件 Meetup

三大 Personal Agent 怎么分

产品 嘉宾共识的定位 短板（发言人说法）
Grokbot（xAI） 像一个虚拟员工团队，偏商务/企业助手；分出多个电子员工协作，小型业务基本能包圆 额度烧得快；主控模型不能自选，模型路由后水平忽高忽低、比较黑箱
Muse（Meta） 像轻量化的生活/社交管家，个人秘书型；跟 Meta 生态绑定深 不适合做商务；视频模型不算特别好，但便宜、"用不完"
Dots（OpenAI） 通知最准（iPhone 原生通知弹出）；适合语音对话、分析代码 只在 100 美元的 Pro 档提供；handoff 到 Codex 时不能指定模型；插件生态难调；群友体感"智商非常低"
  • 共识：每个 Personal Agent 都跟自家生态深度绑定——Grokbot 跟 X，Muse 跟 Meta/Instagram，Dots 跟 Codex 生态；可以搭配着用：工作与内容产出交给 Grokbot，生活中用 Muse
  • 李九二：三个都在用。Dots 通知准但贵；Muse 做视频有时间线，行业新闻基本在 Muse 上看完，还能直接运营 Instagram（发好视频直接发 Ins）；Grokbot 处在 Personal Agent 和 Coding Agent 之间，他有两个账号每天都在用，常拿它当云电脑做测试
  • JKL（本职英语老师，重度用 Grokbot，也办线下活动）：Grokbot 是小企业形态的最佳选择，组织活动、运营、宣发、剪辑、教学基本全包；Dots 只注册了、实际用得少（已被 OpenClaw/Hermes 满足）；Muse 是个人秘书型，不适合商务；国外朋友用 Muse 处理航班延误写邮件 argue，能要到折扣或退款
  • 文哥（xAI 大使）：主要用 Grokbot 和 Muse；Muse 早期用自家模型时中文 AI 味很浓，Muse"说人话"，不用给过多提示、文字就很像人写的；做视频不用特别提示或模板，效果也挺好

铁柱的 Grokbot 省额度六条（本场最实用的段落）

背景：最近大家普遍反映额度烧得很快，官方暗中也有调整；铁柱研究最多，总结了六点：

  1. 能用脚本就不用浏览器：能通过 CLI/命令行完成的任务不要开浏览器——浏览器每一步都要截图识别、判断状态，极耗额度
  2. 重任务分出去：把 Codex 或其他 agent + 其他模型装到 Grokbot 的虚拟机上，Grokbot 只负责分析需求、指派任务、回收结果；中间最重的执行步骤额度就平摊到别的订阅上。重任务包括浏览器任务、大量图片识别、视频拉片分析、做视频（含代码编辑+渲染+抽帧查看）
  3. 定时任务降频：5 分钟检查一次没必要——很多任务一天只变化一次，前面全是空转；每次唤醒都要读记忆、读定时任务上下文、读聊天记录，非常耗额度；删掉没必要的、调低频率
  4. 尽量少用群聊：很多任务没必要用群聊，Bot 之间可以直接沟通；没必要长期保持的群聊，针对单个任务设临时群聊，聊完回收结果就解散
  5. 一个 Bot 做完一件事，别按能力颗粒化拆：一个任务需要多项能力时，多个 Bot 来回沟通的通信本身就很耗额度（新版用量面板能看到）；现在他的做法是尽量让一个 Bot 把一件事做完
  6. 第三方工具注册为公共服务：别给 Codex 单独配一个 Bot 维护；接进来后注册成公共服务，让所有 Bot 都知道、执行时直接调用，省掉中间沟通的额度
  • JKL 的补充打法——"小马拉大车"：Grokbot 只当指挥官，实际工作交给 Codex/Claude/Grok 等下面的 Agent；他从没把群聊拉起来过（好奇时会点进去看 Bot 之间传话）；除了成熟的剪视频让 Grokbot 自己做，其余基本交给别的 Agent；他的额度一直很够用、从没用完过
  • 蓝哥的自述：铁柱说的坑他都踩过——群聊用得多、定时任务也多；改了用法后用量变化很明显

用 Personal Agent 变现：Kim 的四条路

Kim 称社群接龙里问得最多就是"怎么用它变现/搞钱"，他梳理了四个方向：

  1. 跨境电商：与 Grokbot 天然结合最好。选品、运营、投放、数据复盘、竞品调研都极耗人工时间；现在卖家可以搭建很多 Grokbot 军团，效率极大提升——"以前两天能上 100 个链接，现在能上 1,000 个"；时间就是金钱，效率提升赚钱机会就更大
  2. 自媒体：不要觉得自媒体赚的钱少；用 Grokbot 做得好能又快又好地量产内容，接广告、拿推特商单、做付费社群或培训；三人就是受益者——两三个月内快速涨到一万多粉丝，蓝哥一篇 Muse 教程约 200 万阅读、铁柱一篇 Grokbot 微信教程百万阅读；他们在推特公开过收益，"基本每两周就可以拿到接近破千刀"
  3. 2B 企业服务：客单价更高、利润更好。企业的 AI 培训、FDE、帮老板搭工作台、给员工做讲师等；社区后面想帮大家接商单分发给有能力的老师
  4. AI 短剧与独立开发：推特上最火的方向之一是用 Claude 接 Grokbot 做各种 AI 视频；独立开发者用 Grokbot 找新词、快速开发上架网站，"赚大钱不敢说，赚小钱问题不大"；出海方向：早期找需求词、发外链（繁琐人工活，Grokbot 定时任务很好用）
  • JKL 的补充：从本职出发拓展——他把视频发给 Grokbot，剪辑加上传全包；后来让 Grokbot 从百度网盘自动下载活动照片视频、筛选、剪出活动宣传片；佛山一些有见识的小老板已开始用 Grokbot 做小企业/工厂管理的数字团队
  • 木都传的三个具体工作流：① 微信管家：群太多看不过来，用 EO 老师分享的 skill 把微信群记录导到本地，调 Antigravity 整理成 HTML 沉淀到知识库，用 Page 功能分享、发群聊日报；② 设计工作台：刷手机看到好的设计素材链接就发给 Bot，自动沉淀到工作台素材库；③ 公众号运营专家 Bot：Antigravity 写提纲+文案、Codex 配图、套 HTML 格式进公众号草稿箱，推特长文则用 U-Mind 转格式进推特草稿箱；开发修 bug 仍有问题，直接调 Codex 修

国内的 Personal Agent 产品：三款

Kim 分享了他看到的三款国内产品（均为发言人说法，未经核实）：

  1. 特代（Tobay，转写存疑）：国内较早的 Personal Agent 软件，创业公司，核心团队有 Manus 出来的人；融资约 10 亿人民币（发言人称"应该是 10 亿人民币"）；他看好创业公司在这个赛道杀出来，"AI 的世界里如果只有大厂在玩、没有任何创业公司，这个世界会非常无聊"
  2. 吴云串星的 Jabilot（转写存疑）：AI NAS 硬件，把大模型装进本地存储，在本地设备完成语义搜索、转写、文档识别，不靠云、不靠订阅；2025 年在海外众筹平台 Kickstarter 众筹超 140 万美元，总值约 1 亿元
  3. 本为无界的 VLU（转写存疑）：插电脑上的桌面盒子，HDMI 读屏、有键鼠、不用装驱动，支持 Windows/Mac/Linux；2026 年 9 月 Kickstarter 众筹约 2,000 万人民币，订单 8,000 多台 - 另：国内互联网大厂肯定也在密集开发相关产品，"可以拭目以待"；蓝哥补充 Muse 9 月就推出了硬件组件，可接入 Muse 生态

开源 Personal Agent 还在用吗

  • GKL 提问：现在各大厂的 Personal Agent 如此盛行，你们还有在用开源 Personal Agent 吗？
  • 蓝哥：还在用 Hermes（转写"黑马斯"）；原因：Grokbot 的模型没法选，主控模型一定是它自己搭配的（很可能就是 Grok 4.7，评测整体比其他几家偏弱）；Hermes 什么模型都可以配
  • Hermes 的取舍：确实重，但可以做职责分工、有沉淀记忆；只用 Codex 会以 session 分工，session 可能很膨胀；Hermes 每次更新会覆盖他个性化定制的插件，这是他一度弃用的原因
  • 顾德昊：在用开源的 RAKAGO（转写 "r a k a jio"，类似 Grokbot，有移动端+PC 端），做了深度开发；用途是企业级服务补充——Grokbot credit 太少，且税务自动申报这类场景不适合用 Grokbot；企业客户不能都推 Grokbot

X 自动化发帖：API 可以，computer use 会封号

  • Steven 的问题：Grokbot 自动化发帖前天/昨天突然出问题了，有没有人遇到过？
  • 铁柱的经验：他只让 Grokbot 做信息收集（每天 9 点和 12 点收两次 X 的信息、看帖子访问量、做选题），不让它发帖；自动发帖流量掉得很狠，还有封号风险；他用小号测试过，跑了两三周一直没问题，但不建议这么做
  • 蓝哥：推特本质是社交、像朋友圈，不互动就失去了来推特的意义；全自动很难得到连接与乐趣
  • 铁柱补充：推特官方支持自动发布，有官方 API；不推荐的是用 Grokbot/Codex 的 computer use 操作浏览器去发，"铁定违反推特条例"，会遇到封号或影子封禁；用 AI 在别人帖子下面回评论"一点收益都没有"，除了招人反感还亏 token
  • JKL 亲身经历：不知道有 API，就让 Grokbot 用 computer use 在浏览器发帖，"喜提封号"，申诉后放出来了；后来才知道用 Grokbot 会得到 100 美元的 X 平台 API 额度，用 API 发帖就没问题
  • 共识：工具不重要，方式才重要——通过官方 API 发没问题，通过浏览器 RPA 操作就是违规；Muse 也一样

多场景、多设备的上下文管理

  • 愿明水晶神（李竹）的问题：产品开发+自媒体+出海 SaaS 站，事情很杂，工具也多（OpenClaw、Hermes、Codex、Gemini、Grokbot、Claude），上下文散落在很多地方，skills 也不统一；有没有好的工具降低迁移成本、统一入口？
  • 铁柱：用 Grokbot 建 Bot 做分配；或以人为中心、用 ADE（Agent Development Environment）聚合——ORCA、T3code 都是新的 ADE 产品
  • 听说老师的方案：三台电脑+三台服务器，Obsidian + GitHub 私仓做唯一真源，Syncthing 插件同步到每个地方；设定只有一个老大可以写入；每次对话归纳总结、提取重要信息写入知识库；自今年初用下来，"基本上就没有再出现失忆或者打架的事情"
  • 另一位嘉宾：早期也用 Obsidian，后来迁到 Notion（Grokbot 的唤醒机制写本地文件系统不便）；现在用 Muralsim（本地 ADE，把大任务拆分、支持定制 Bot、聚合本机所有 ADE 产品），用得比 Grokbot 还多；Grokbot 不能自选模型是硬伤
  • Wayston 的方案：一切以 GitHub 为本源，每天定时把所有数据同步到 GitHub；飞书做协作与输出呈现；本地一切用 AGENTS.md 做主要支柱，其他与生态相关的文件都让模型去读 AGENTS.md，"脱离某一家大语言模型的生态绑架"；用 SDD 形式推进产品研发

项目管理痛点：张坤的微信群机器人问题

  • 张坤的现状：做项目管理，工作上一直用 Grokbot；总控 Bot + 写文档/浏览器/编程 Bot；用 Webhook 把 Bot 接入客户微信群自动回答问题；有五六个项目、很多群
  • 痛点：客户提问不能及时回复，有些问题要改文档、改工具；Grokbot 队列一次只能执行一件事，不能并行；想实现"super agent"理念——问题自动记录、自动执行、人工复核
  • 讨论结果：① 铁柱建议自己搭服务+多个 webhook 隔离不同群（他在 WayToBot 每个群都拉了一个"小铁柱"，但只限自己 @，因为 webhook 一小时只能发起 200 次）；② 顾德昊建议接自己的 helpdesk/Ticket 系统，AI 自动运营，甚至把权限交给 Bot、让它自动开发和改系统；③ 本地 Hermes 方案没人实测过，留待后续活动再聊

工具分流实测与踩坑

  • 赛博弗兰克：一个任务让所有 Bot 都做、看谁做得好；写公众号用腾讯的 Lightweiler 最好，自动进公众号草稿箱，但缺人味、曝光忽高忽低，测了一个月；视频交给 Hawk；YouTube 国学（八字风水）账号更新一个多月，订阅几十、阅读几百上千，还没变现；自己在做 Agent 硬件（类似 VLU），Hermes 装龙箱老断，最近 Hermes 推了新品 Xdudu，打通硬件与手机电脑
  • 李叔：Grokbot 额度焦虑后也在用 Muse 和 Hawk；Bot 从很多个精简到五六个，"一人多专"；Hawk 做视频要求越具体越复杂、质量越高，已达到 OPOS 5.5 级别；会全网找公版版权音乐并署名；教训：让它一次生成 500 张 Midjourney 照片、开了 4 个浏览器窗口跑完、质量很高，但 Midjourney 号被临时封了（申诉中）——"使用这些 Agent 的时候还是要控制一下边界"
  • Hawk 的免费额度：每天重置一次，额度较少；李叔的办法是三四个浏览器各注册一个 Hawk 账号、按类型分开用
  • Wayne Wang：Muse 做视频对比过 MiniMax、Cdance、中转平台，Muse 出来的视频最符合要求、AI 味不重、很真实、质感好；用 Muse + Codex 操控手机自动发 TikTok/Facebook/IG/Twitter；最近 Muse 遇到地区限制生成不了视频、封了两三号；铁柱解答：路由切到支持的区域，他的 Muse 所有路由（含 Facebook/Meta 路由）全走美国节点
  • AirLinz：Muse 自动发推/Facebook 的办法是装一个谷歌插件，绑定 Meta 账号即可自动发

值得留意的几条线

  1. 省额度是本场共识第一痛点：铁柱六条 + JKL"小马拉大车"，核心就一句——Grokbot 当指挥官，别让它干重活
  2. 变现路径已经有人跑通：三人两三个月涨粉一万+、每两周近千刀收益；跨境电商是 Kim 最看好的方向，Grokbot 军团把上链接效率从两天 100 个提到 1,000 个
  3. 国内 PA 正在补位：软件（特代）+ 硬件（AI NAS、桌面盒子）三条线，12 月 12 日深圳还有 Grokbot + 硬件 Meetup
  4. X 自动化发帖的红线很清楚：官方 API 可以，浏览器 computer use 会封号——JKL 是亲身封号案例
  5. 多 Agent 时代的真正瓶颈是上下文：Obsidian + GitHub 唯一真源、AGENTS.md 防生态绑架、ADE 聚合，三种解法同场出现，说明这已是重度用户的共同痛点
